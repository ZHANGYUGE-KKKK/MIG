# 在线独立读请求并发对照（800MT/s）

2026-10-29。状态：实现与上板完成。3次重新配置/校准、24轮累计读取384MiB，0错、fatal0；实际在途峰值30。见[实测报告](hardware/2026-10-29_results.md)。

保持online_diag的颗粒、频率、电气配置、引脚、PRNG、1MiB区域、写突发、16遍交替和VIO/ILA/UART功能。区别仅在读取事务发生器及相应观测：

- 密集遍：ARLEN=0，每个读请求16字节，最多32个独立AXI请求在途，RREADY持续可接收，使用相同ID并按AXI要求顺序比较。
- 稀疏遍：ARLEN=0，一个请求在途，每次返回后额外100 UI周期间隔。
- issued_index与read_index分开计数，只有真实握手才前进；按同时AR/R握手更新pending，达到32上限后等待返回再继续发。
- 记录实测peak_outstanding，不把设置的32上限当作实际达到32。首错记录padding新增模式标记和峰值，原首错字段位置不变。

仿真故意延迟首批R返回，以填满32项，正常及DQ9注入用例断言peak=32；验证256个读取数据拍、注入2个DQ9错误、RLAST/BRESP异常、超时及校准丢失。写入仍与独立Python PRNG表对照。硬件实现/时序/引脚/数据结果不得用仿真结论替代。

本工程比单请求32拍更接近旧native多命令负载，但仍经过AXI到MIG内部命令转换，不含原native比较FIFO，因此不是旧应用逻辑逐行复测。用户调整后电压精确读数待补；不作电压单变量因果结论。
