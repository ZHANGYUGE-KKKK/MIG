# 800 MT/s 全容量连续突发压力

2026-10-29，用户要求800最高压力，在online_800_full单拍密集/稀疏对照之外新增本工程。已完成16轮全容量实测：写16GiB、读256GiB，0错/fatal0；实测2个32拍突发在途。见[实测报告](hardware/2026-10-29_results.md)。

配置沿用800：CK400/UI100MHz，单rank x16、完整1GiB，CL6/CWL5、1.5V、原ODT/驱动/引脚。参考250MHz。只JTAG下载，Flash不变。

每轮先以32拍写突发覆盖全区，再连续密集读取16遍。读ARLEN31、每次512字节、最多32个独立AXI突发请求在途，同ID保持返回顺序。按RLAST统计在途请求，逐拍比较并检查第32拍RLAST；RREADY在有在途事务时持续有效。没有人为稀疏间隔，是否达到32在途以ILA实测为准，不将配置上限当实际峰值，也不声称理论带宽已饱和。

数据为online_800_full地址相关PRNG的逐位取反，扩展模式覆盖；每轮所有地址先写完，再读16遍，期间不重写。区域标志0为1MiB，1为1GiB，默认运行完整区域；每轮写1GiB、读16GiB。

此版专用ILA签名AXB8，解码器拒绝其他镜像签名。所有16个leg均是密集读，不能沿用奇偶遍分类，decoder已分别处理。结果记录总错、逐遍错、各DQ翻转、首错、协议/超时/校准fatal、写/读计数和峰值并发。脚本额外保留整轮墙钟时间，包含UART报告等待及ILA触发少量开销，不能当纯DDR有效带宽。

七种仿真：正常、DQ9注入、提前RLAST、BRESP错误、事务超时、校准丢失、动态大区域；独立Python生成4096拍互补期望表，模拟随机AW/W/AR/R背压并达到32在途。全容量边界另按实际生成参数和地址宽度核查，不称缩小模型仿真已遍历1GiB。

仍不包含混合读写、随机访问、DM掩码、全部数据模式、冷启动温度范围。通过只表明所记录条件下的数据比较正确。
