# DDR3 RTL 压力测试方案

状态：压力测试 RTL、独立构建和用户接口级仿真已实现；Vivado 实现验证及产物状态见 `TEST/RESULTS.md`。操作说明见 `VIVADO/stress/README.md`。2026-10-25 用户确认现有裸机 HELLOWORLD 测试通过；该反馈不等于全容量或长期压力测试通过，也未据此推定具体供电返修步骤。

## 第一版范围

保留现有顶层、MIG、引脚、时钟、复位、UART 和 GPIO LED 7。不增加应用 CPU、AXI 或操作系统。现有 HELLOWORLD 单突发版本作为可回退基线保留。新压力测试采用独立 RTL 模块及独立构建输出，先生成 bitstream 及配套压缩 Flash 镜像供后续使用；上板优先用 JTAG SRAM 验证，稳定后再烧入 Flash。若实物 JTAG 的 FMC 旁路尚未补齐，需要先恢复调试链路，或另行安排断电拆装与 Flash 更新，不假定该限制已被修复。

当前配置：MT41K512M16HA-125，x16、8 Gbit = 1 GiB，1600 MT/s，MIG UI 200 MHz / 128 bit。保持当前频率，不把提高频率当作第一步压力测试。

## 地址和数据规则

- 每个原生用户接口数据拍 128 bit = 16 字节，对应 x16 DDR3 的一次 BL8。
- `app_addr` 是 DRAM 字地址，每个突发步进 8，而非步进 16。
- 全容量共有 2^26 个突发；全容量有效突发起始地址为 0..0x1ffffff8，均按 8 对齐。对外日志同时输出原生地址和逻辑字节偏移（原生地址乘 2）。
- 扩容顺序：1 MiB → 64 MiB → 1 GiB。所有测试均会覆盖所选 DDR 区域原内容；本系统无应用 CPU 或其他 DDR 使用者。
- 必须先写完整个选定区域，再读完整个区域做比较；不能仅逐地址写后立刻读，否则可能漏检高地址别名。
- 地址相关数据中至少包含完整突发索引，并为 128-bit 内不同字节/字设置不同内容。避免全空间同一常量或 4 个完全相同的 32-bit 字遮蔽地址/位序故障。
- 伪随机数据由地址、数据通道和固定 seed 可复现地生成；读回端根据命令记录重建期望值，不必在 FPGA 内缓存整颗 DDR 的镜像。
- 伪随机访问采用可复现的双射地址置换，例如在 26-bit 突发索引空间使用奇数步进和不同起点，保证一轮覆盖所有突发，而非无覆盖保证的随机抽样。

接口依据：AMD PG150 app_addr / User Interface / Write Path。

## 自动运行阶段

| 阶段 | 行为 | 主要目标 |
| --- | --- | --- |
| 小范围自检 | 先 1 MiB，后 64 MiB，固定模式及地址相关模式 | 验证新 RTL 和基本链路，尽早定位错误 |
| 全容量模式覆盖 | 1 GiB 全区写入再全区读回；依次全 0、全 1、AA、55、地址、地址取反、地址相关伪随机 | 覆盖容量、地址别名、数据位、模式敏感错误 |
| 顺序连续带宽 | 连续发写数据/命令；整区写完连续发读并比较；每轮换 seed 和地址方向 | 高占用读写、翻转活动及实际吞吐 |
| 地址置换和读写切换 | 全区初始化后置换读；另以可配置块大小（默认 4 KiB）反复写新 seed 后读回，切换访问地址 | 地址跳变、读写周转、不同 bank/row 访问 |
| 持续循环 | 交替重复上述连续和切换测试 | 累计访问量及长时间稳定性 |

行走 1/0 可作为小区域专项测试加入，不将 256 次全容量遍历放进每次快速启动自检。

第一版的读写混合采用有明确依赖的块级写/读切换：选块 → 写入本轮新数据 → 读回比较 → 等待读返回全部收齐 → 进入下一块。不对同一地址无序混用不同版本数据，避免期望值跟踪错误或因反复写相同值掩盖写入故障。

可追加正常刷新条件下的空闲等待后读回检查，但不关闭刷新，不把它宣称为完整的器件保持时间测试。重复复位和断电重启单独作为硬件测试项目，保留正常校准流程。

## 高吞吐实现

- 新增地址/数据发生器、原生接口调度器、读返回比较器、有限深度期望值 FIFO、统计与错误记录模块。
- 写数据和命令使用独立计数器和握手；数据可先于对应命令进入 FIFO，只有存在已接收数据时才发对应写命令。保持稳定数据/命令直到各自握手，避免命令先行后数据迟到。
- 连续读允许多个命令在途，第一版最多 32 个。仅在读命令被接受后压入地址和期望数据，按有效读返回消费，防止 FIFO 溢出/欠读；检查每个 128-bit 返回的 end 标志。
- 一个完整写阶段必须确认命令和数据各接收 N 次；完整读阶段必须发出并收回 N 个突发，不能将请求被接受等同于所有读回已经完成。
- 串口通过状态快照/FIFO 取得统计，发送速度不反向限制 DDR 发生器。
- 32 个在途请求只是调度上限，不代表一定达到峰值。以实际测得吞吐和数据一致性判断。

## 状态与错误

GPIO LED 7 保持表示 MIG 校准完成。现阶段不新增其他 LED 引脚；活跃、通过和错误状态先通过 UART 表达。

115200 / 8N1，每 5 秒请求一次摘要，阶段/模式切换也请求快照（串口忙时合并为最新状态）：阶段、模式、seed、覆盖容量、完成轮数、运行秒数、累计写入和读回字节数、读/写吞吐、错误次数、最大在途读数。

吞吐口径：写入字节按 MIG 已接受写数据计数，读字节按已发请求的实际有效返回统计；写数据和命令另有独立握手计数，确认都完成后才进入读阶段。故障时 W 可能包含最多 512 B 已接受但命令尚未匹配的写数据。用 UI 周期计时，原始速率字段为 KiB/s，监视脚本转换为 MiB/s。累计计数用 64 bit。不得将这些应用层数据量当成包含刷新/命令开销的物理总线利用率。

第一次错误立即锁存并停止继续发新请求，保留日志；已发在途读在有界超时内收尾。输出：原生地址、字节偏移、期望/实际 128-bit 数据、XOR、模式、seed、阶段、轮次、运行时长。错误记录不被后续 UART 输出或复位前的其他错误覆盖。复位会清除本轮易失统计，故首错先打印保存。

独立报告 CAL_TIMEOUT、CAL_LOST、WRITE_DATA_TIMEOUT、WRITE_CMD_TIMEOUT、READ_CMD_TIMEOUT、READ_RESPONSE_TIMEOUT 及 DATA_MISMATCH。看门狗检测某阶段长时间无进展，不能将一次容量较大的合法运行简单限制为总共 10 秒。

## 验证与上板节奏

1. 用户接口级仿真使用缩小容量，检查顺序及置换访问覆盖、边界/回绕、期望值 FIFO、独立握手背压、多笔在途返回、超时和错误注入。注入地址别名和单 bit 数据错误，确认能检出并打印正确首错。
2. Vivado 综合、布局布线、时序、bus skew、DRC，生成独立 bitstream 和压缩 Flash 镜像。仿真不能代替实际 DDR3 校准和硬件读写。
3. 上板先跑 1 MiB、64 MiB，再扩展到完整 1 GiB，确认没有错误和超时。
4. 首轮全容量持续跑 30 分钟；通过后再跑 8–12 小时。期间不为读取统计暂停 DDR 流量。
5. 通过条件：相应测试已实际完成，所有有效读均比较一致，累计错误为 0，无失校准、无超时。记录环境、实际供电、配置和累计读写量。
6. 只将达到相应覆盖/时长的结果记作该等级通过，不把短时间自检 PASS 等同于长期稳定性通过。
