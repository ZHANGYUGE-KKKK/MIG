# 低负载线序验证方案

日期：2026-10-26。状态：方案，尚未实现或上板验收。

## 目标与结论边界

本轮暂停1600 MT/s。保留已核实的VRP800 MIG及引脚，以降低事务发起速率的方法执行基本功能覆盖。

必须区分逻辑功能与物理网名对应：同一字节内DQ置换若写入与读回经过相同置换，回环仍可能完全通过；某些地址/Bank置换也可能只造成物理位置重排而不混叠。因此程序可以验证全地址可区分、数据模式可保存、掩码有效，却不能单独证明FPGA每个网名接到了指定DDR球位。物理线序最终需原理图/PCB网表端点对照与断电逐针导通检查。无法直接触及BGA球位时，应注明测量端点及未覆盖段。

## 运行条件

- DDR总线800 MT/s、UI 100 MHz、参考250 MHz保持不变；降低的是读写事务速率，不能据此称DDR电气速率低于800 MT/s。
- 单笔在途读，上一笔数据完整返回并比较后，额外等待1 us再发下一笔；写数据/命令握手完成后也等待1 us。保留10 us档用于失败后对照。实际间隔包含控制器延迟。
- 不执行并发压力。首错、错误总数、位/拍分布、实际写读数及完成标志均记录；读写不匹配继续统计，校准丢失/协议异常/超时单独标记。
- JTAG和DDR无法共存：断DDR烧写双Flash→完全断电→接DDR→Flash启动→UART采集。LED7保持校准指示。

## 测试顺序

1. **数据位**：多个低/高地址和Bank/行边界测试128位突发行走1、行走0、全0、全1及交替模式。覆盖16个DQ×8拍。定位数据位相关错误，但不把通过解释为排除了可逆DQ置换。
2. **DM掩码**：先写基准数据，逐字节只允许一个字节改写，检查目标字节和其他保持字节；覆盖128位UI的16个字节及两根物理DM对应的各拍。仅不带掩码的整突发读写不能验证DM。
3. **地址别名**：以0和最高突发地址等多个锚点，与逐个翻转的有效突发地址位组成地址集合，写入各不相同的标记；必须全组写完才统一读回。反相数据并倒序写读重测。校验各锚点及所有偏移地址互不混叠。
4. **全容量**：整1 GiB先写完地址相关且可区分的数据，再整区读回；互补模式再做一次。覆盖67,108,864个16字节突发，包含低高边界及全部Bank/行/列组合。必须从生成的MIG地址映射列出逻辑位与物理地址字段对照，不能仅靠遍历计数声称逐针覆盖。
5. **物理对应**：按50根DDR信号的端点表核对FPGA封装脚→母板FMC→转接板→子板→DDR球位；结合断电导通/相邻短路检查记录PASS/FAIL/未测。此项与读写功能结果合并，形成线序结论。

当前native app_addr宽29位，BL8每突发16字节；突发号26位，app_addr=突发号<<3，范围0至0x1ffffff8。native低3位的突发内位置由8拍数据模式覆盖，不发非对齐突发来代替。实际物理行/列/Bank字段须依据生成RTL的ROW_COLUMN_BANK解码逐项确认。

## 实现与验收

独立目录保存RTL、仿真、解码器和构建产物，保留既有镜像。仿真检查握手背压、全组写后读、地址端点及覆盖、掩码、超时；注入地址混叠和数据位错误验证检错能力，也加入可逆置换仍能通过的模型以明确测试边界。完成后生成并校验双MCS；UART各阶段必须有实际计数和结束记录。每次上板将镜像散列、条件、原始日志、统计、判断及未覆盖项写入DEBUG_LOG/RESULTS。
