# DDR3 数据错误受控定位计划

> 此为历史计划。当前执行顺序见 [TODO](TODO.md)，完整证据见 [DEBUG_LOG](DEBUG_LOG.md)。用户已明确JTAG与DDR链路无法共存；下文依赖在线JTAG/ILA的建议已由新计划替代，不再作为当前前置条件。

状态：第一优先级的同镜像372组诊断已实现，仿真/实现/双Flash固化通过，实物372组已完整执行但数据失败（累计124738次错误突发）。源码和操作见 VIVADO/probe/README.md。现有单笔读仍报数据错误，最新实物结果见 RESULTS.md。

## 现有证据

- 原32笔读版：1 MiB全1、原生地址0、UI bit65（DQ9第0拍）1→0，多次复现。
- 单笔读版：1 MiB模式0..7完成，行走0、原生地址0x19FE0、UI bit124（DQ12第7拍）0→1。
- 两个错误位都位于 DQS1 对应的 byte lane1，但不足以定位到某个器件；当前1 MiB测试尚未完整通过。
- 两版不只请求密度不同，期望FIFO规模及物理布局也不同，诊断版还补充复位CDC输入约束。故不把两版差异当成已证明的某个逻辑缺陷。

## 第一优先级：同一个镜像中的固定内容与读写分离

在同一1600 MT/s、同一布局布线的诊断镜像中，自动串行执行以下有限测试；阶段切换前收齐在途读、匹配完写数据/命令。数据错误按阶段计数并保存前N个样本，避免只见到首错；校准丢失、UI reset、协议异常和握手超时仍停止。UART输出阶段摘要，不逐次打印全部读返回。

| 测试 | 操作 | 判断线索及限制 |
| --- | --- | --- |
| 写一次，多次读 | 对地址0、0x19FE0及邻近突发，分别写固定全1、bit65为0/1、bit124为0/1等模式；同一次写入后，不改内容，读同地址1万次；多组间重新写入 | 不重写时读值变化，优先查读路径/采样及受扰数据；始终返回同一个错误值，优先查写入、单元或固定读路径。稳定错误也不能单独证明是写故障。 |
| 移动首地址与读取顺序 | 初始化小区域后，让已知失败地址分别成为第一笔、中间笔、最后一笔读；将相同模式移到其他地址 | 错误跟随物理地址，优先查单元/地址相关路径；跟随第一笔或特定拍，优先查启动、周转和采样时序。逐地址立刻写读仅作定位，不替代整区写后读的别名测试。 |
| 同镜像改变流量 | 固定FIFO深度32，通过运行时限制切换1/2/4/8/16/32笔读；写队列也分别限1和32；增加写→读间隔及读命令间隔0/16/64 UI周期 | 比较写/读负载与间隔对错误率的影响；FIFO结构与比较器保持固定，避免每个设置重新生成 bitstream。间隔改善只是流量/时序相关线索，不能单凭此区分SI、供电和MIG/应用交互。 |

统计：每阶段实际命令/数据接收数、读返回数、错突发数、每个UI位/DQ/byte lane/拍的错误次数；错误记录包括地址、期望、实际、XOR。正常情况下判定正确性基于逐拍比较及覆盖数，不以cal=1代替PASS。

当前只有UART TX，因此优先让模式自动顺序执行；可选择增加VIO控制。使用VIO/ILA或读取MIG窗口要求插卡时JTAG链路可用；此前母板侧D30/D31返回链路问题需确认，不假设已修复。

## 第二优先级：校准裕量和速率对照

1. 在**校准成功的同一次运行**读取MIG read/write margin，重点比较byte1的DQ9（bit1）、DQ12（bit4）与该组其他位、byte0，以及读上升/下降沿。不要把校准失败时未填充的0当作测得的窄窗口。校准窗口用于定位裕量，不等于完整运行时眼图或转接板单独的合格证明。
2. 保持相同测试逻辑、模式、地址、单笔读条件与环境，做800 / 1600 MT/s对照；800 MT/s须确认MIG/颗粒合法配置，并同步匹配CL/CWL、UI时钟、UART及计时。Si570输入不随意改变。两种速率不可避免需不同MIG实现，记录这项物理实现差异。
3. 若低速反复通过而高速失败，优先查速率相关裕量、布线/终端/供电及PHY配置；这不能单独证明一定是转接板设计问题。低速仍错也不能直接认定为纯逻辑问题。

AMD官方支持读取每位读/写窗口；Hardware Manager中可用 `report_hw_mig [get_hw_migs]`。关注 RDLVL_MARGIN_PQTR/NQTR_LEFT/RIGHT 和 WRITE_DQS_DQ_MARGIN_LEFT/RIGHT。

## 第三优先级：独立发生器与硬件分段

- 以同一MIG配置、时钟和50根引脚，生成并验证AMD官方example design/traffic generator。匹配数据模式、地址、负载和测试时长。官方发生器也错，降低自写调度/比较器是唯一原因的可能性；只在自写版错，重点用ILA检查应用握手和数据，仍须考虑不同布局及流量条件。
- ILA同时捕获被接收的写数据/掩码、写命令/地址，读命令/地址、valid/end/实际数据、期望值及首次错误触发。先确认UI请求正确，区分应用比较/日志问题与上游返回差异。UI捕获不能代替DDR引脚模拟波形测量。
- 若有已知正常的兼容转接板或DDR子板，保持代码、设置、供电及连接方式一致，一次替换一件。故障随转接板或子板移动，是比仅观察PASS/FAIL更直接的硬件定位证据；连接器接触状态也需记录。
- 断电逐线检查转接板导通、邻线短路、差分极性、字节组及地回流连接，重点DQ9/DQ12/DQS1/DM1。这能检查线序和装配，不证明1600 MT/s信号完整性。若具备适当的高带宽低负载探头，可按官方方法在写入接收端（DRAM）和读取接收端（FPGA）测DQ/DQS关系；普通长地线探测可能改变被测波形。

## 推荐实施顺序

先做固定写入→反复读＋改变读取顺序；在同一镜像内自动切换间隔/并发并统计错误位分布。随后读取成功校准的裕量，再做速率对照。仍不能定位时，结合官方发生器、ILA与有条件的硬件替换。未满足这些条件前，不把测试失败等同于“转接板设计错误”，也不把一次通过等同于“设计已可靠”。

## 官方依据

- AMD PG150 [区分写错误与读错误](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/Determining-If-a-Data-Error-is-Due-to-the-Write-or-Read)：少量写入后持续读、检查一致性、结合DQ/DQS测量。
- AMD PG150 [隔离数据错误](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/Isolating-the-Data-Error)：按DQ/DQS组、地址、模式、温度/电压及可复现性分类。
- AMD PG150 [分析读写裕量](https://docs.amd.com/r/en-US/pg150-ultrascale-memory-ip/Analyzing-Read-and-Write-Margin)：读取读上升/下降沿及写入的逐位窗口。


### 2026-10-25完整实物结果

372组镜像已完成双Flash擦除/编程/读回校验（7分59秒），用户断电接好DDR链路并重新上电后，完整日志覆盖job0..371（0x173），无致命故障，但累计124738次错误突发，未通过数据测试。类型5的0x173记录是结束摘要重复发送，不是重新运行。

固定写入反复读及顺序切换48组均通过；1 MiB负载对照有135/324组出错。读间隔0/16/64额外UI周期对应124644/47/47次错误，明显与读取密度相关，稀疏访问仍有残余错误。byte1为主要错误组，同时byte0也有错误，尚不能单独定位到转接板。插板后JTAG未检测到FPGA，未取得有效校准裕量。完整表、原始文件副本和判断边界见 `TEST/probe/hardware/2026-10-25_cutecom_uart.md` 及同名JSON；硬件文件散列见 `VIVADO/probe_build/hardware_manifest.json`。
